2. autoexit. Champ booléen facultatif `autoexit` accepté par POST /api/tasks (et POST /api/tasks/<id>/edit), validé strictement (booléen), stocké dans la ligne du plan sous la clé `autoexit` (supprimée si faux), relu à l'enqueue d'une tâche connue du plan, porté par Run.autoexit (persisté) et exposé dans GET /api/runner. Comportement : pour un run `autoexit` en état `waiting` (fin de tour + terminal muet) CONTINÛMENT depuis AUTOEXIT_GRACE_S (45 s par défaut, surchargeable pour les tests par option de ligne de commande ou variable du Runner) ET dont le transcript ne contient AUCUN tool_use sans tool_result (question à l'utilisateur, demande de permission, outil en cours : dans ce cas on ne fait rien), le serveur écrit `/exit\r` dans le pty (une seule fois, notice cat « runner » kind `runner_autoexit`, severity info) ; si le processus n'est pas sorti AUTOEXIT_KILL_AFTER_S (20 s) plus tard, il appelle stop() (SIGTERM puis SIGKILL après STOP_GRACE_S). Le run sort alors normalement (done si code 0). Un run sans autoexit n'est jamais touché. Si l'agent reprend du travail (réactivité du terminal), le délai repart de zéro.
