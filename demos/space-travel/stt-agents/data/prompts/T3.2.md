COMMANDES (sortie JSON sur la sortie standard par défaut, `--pretty` pour l'indenter ; messages d'erreur sur la sortie d'erreur ; codes de sortie : 0 succès, 1 échec de l'opération, 2 erreur d'usage, 3 serveur injoignable ou jeton introuvable) :
- Option globale `--url` (défaut variable d'environnement STT_AGENTS_URL, sinon http://127.0.0.1:8765). Le client REFUSE tout hôte non bouclé (127.0.0.1, localhost, [::1]). Découverte du jeton : GET `<url>/`, balise `<meta name="stt-token" content="…">` ; jamais affiché ni journalisé ; en-têtes envoyés : X-STT-Token et Origin = l'URL de base.
- `submit` : `--lot L --title T --agent dev|archi|revue --model opus|sonnet|haiku --cx XS|S|M|L|XL (--prompt TEXTE | --prompt-file F) [--prio 1|2|3] [--worktree W] [--base BRANCHE] [--perm acceptEdits|plan|manual] [--docs F:lu|modifié|créé …] [--no-autostart] [--no-autoexit]` ; autostart ET autoexit sont ACTIFS par défaut ; POST /api/tasks (le corps contient `autoexit: true`) ; affiche {id,budget,prompt,state}. Le fichier de prompt est lu en UTF-8 et ne doit pas dépasser 400 Kio.
- `list` : GET /api/runner → liste compacte (task, agent, model, state, exit, worktree, inst, tokens, started, ended) ; `status <task>` : une ligne détaillée du run.
- `report <task>` : GET /api/runner/<task>/report (forme : {task,state,exit,session,started,ended,final_text,usage:{input_tokens,output_tokens,cache_creation_input_tokens,cache_read_input_tokens,total_tokens},duration_ms,tool_calls,files_modified,last_activity}) ; option `--kanban` : produit en plus un bloc `kanban_add` {"used": total_tokens, "ms": duration_ms} prêt à coller dans une opération `task` du Kanban.
- `wait <task> [--timeout S=3600] [--interval S=5] [--until done,failed,stopped,killed]` : interroge /api/runner jusqu'à un des états demandés ; imprime le dernier état ; code 0 si `done`, 1 sinon, 4 si le délai est dépassé ; reprend sans erreur si le serveur redémarre pendant l'attente (réessaie jusqu'au délai).
- `pause|resume|stop|kill|cancel|enqueue <task>` : POST /api/runner/<task>/<action> ; `input <task> --text T` (échappements \n \r \t interprétés) ; `exit <task>` : envoie `/exit\r` ; `resize` inutile.
- `kanban-ops FICHIER.json` : POST /api/kanban avec l'en-tête X-STT-Kanban:1 (corps `{"ops":[…]}` ou liste) ; `--dry-run` ajoute `dry_run:true`.
Erreurs HTTP : affiche le code et le message du serveur (400/403/404/409/413/429) sans trace Python.
