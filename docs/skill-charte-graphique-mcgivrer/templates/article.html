3D City — building a GTA-like sandbox from scratch

Frédéric Delorme • 2026-08-30 • 8 min read

Java Game dev 3D

This is a 3D version of ASCII City, this time with actual vehicle models and a handful of new missions. The goal was the same as the original: no game engine, no external dependencies — just the JDK, a software rasterizer, and a lot of trigonometry.

The project started as a weekend experiment to see how far a from-scratch renderer could go before the frame budget ran out. It turns out a city block of about forty buildings, a dozen roaming vehicles and a simple day/night cycle all fit comfortably inside 16 ms per frame on a laptop CPU.

Why no engine?

Reaching for Unity or Godot would have solved the rendering problem in an afternoon — which is exactly why I didn't. The interesting part of this project was never "ship a game", it was "understand every pixel that ends up on screen". Writing the rasterizer, the depth buffer and the camera frustum culling by hand is what made the exercise worth doing.

The best way to learn how a renderer works is to be forced to fix the one you just broke.

The vehicle models

Each vehicle is a small OBJ-like mesh baked into a Java array at build time, no runtime parsing involved. A minimal example of the format looks like this:

record Vertex(float x, float y, float z) {}
record Face(int a, int b, int c, int colorIndex) {}

record Mesh(Vertex[] vertices, Face[] faces) {
    // ~120 vertices / ~200 faces for a compact sedan
}

Have fun exploring the city, and let me know which mission felt the most GTA-like.
